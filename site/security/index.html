ON THE SERVICE

Opaque storage and controls

  • Encrypted envelopes and opaque bucket IDs
  • Ciphertext sizes and timestamps
  • OAuth identity links and hashed service tokens
  • Quotas, rate limits, and short-lived security records
01

Authenticated access

OAuth uses PKCE and short-lived, single-use exchange codes. Backup keys are random and stored as hashes. Extension callback destinations are restricted to configured extension IDs.

02

Compartmentalized secrets

OAuth client secrets and the administrative token are Worker secrets, not extension code. The service never receives the vault password or derived vault keys.

03

Open implementation

The extension, protocol, server, migrations, tests, and deployment configuration are available for inspection. Self-hosters can operate the same API with their own identity providers and storage.

What encryption does not hide

The service can still observe the service-account identity, bucket count, approximate ciphertext sizes, API endpoints, request timing, and short-lived IP data used for abuse prevention. Review the privacy policy for retention and user choices.
